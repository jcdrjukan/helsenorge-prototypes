# Prøvesvar

Static HTML prototype for the Helsenorge **Prøvesvar** (test results) service. Started 2026-10-08 as an empty shell; content will be built up partly from Figma.

## Current state
- `index.html`: the Helsenorge chrome only: header with profile bar, "Forside" breadcrumb (goes nowhere yet), Språk/Language switcher, a PageHeader rebuilt from the live Prøvesvar page's markup (title "Prøvesvar" and a favoritter star copied from Gravid that toggles and is remembered in the browser), the real ingress ("Her finner du svar på prøver og undersøkelser, for eksempel blodprøver, røntgen, MR eller CT."), a HelpExpanderStandalone "Velg om du vil få varsel om prøvesvar" (from the live markup; opens draft text: "Du får ikke automatisk varsel når et prøvesvar er klart. Vil du ha varsel, kan du slå det på i varselinnstillingene dine."), a Spacer (s), then a sticky white Tabs section breaking out to full width (from the live markup): **Prøvesvar** has the filter row ("Finn ..." FilterButton, inert; "N prøvesvar" count; a working "Sortering:" select by date, område or rekvirent, default newest first) and an outline PanelList of 9 white Panels (område title, rekvirent, "Prøvedato", borderless "Se resultater" with ChevronRight, not linked yet) using the live page's test data; **Analyseoversikt** (navigate by prøvesvartype, from the live markup): a "Søk i listen" FilterSearch that filters as you type (analyse, område, date; "Ingen analyser passer søket." when empty), Spacer m, and a HorizontalScroll with a sortable Table (Analyse / Område / Antall svar / Siste prøvedato; default Analyse ascending; click a header to sort, again to reverse; edge shadows when it can scroll) of the 26 analyses from the live test data. Each analysis name (AnchorLink) opens its analysis page. Then a Spacer (s); the feedback form "Hvor fornøyd er du med tjenesten Prøvesvar?" (five plum face radios, Misfornøyd … Veldig fornøyd; selecting one marks it, nothing is submitted); Spacer (l); the title2 "Personvern for Prøvesvar"; Spacer (m); a line LinkList with "Logg over bruk" and "Personverninnstillinger" (not linked); then the black footer, and the desktop phone frame.
- `resultat.html?id=N` (detail page for all 9 results, rendered from a `RESULTATER` object; every "Se resultater" on the list links to its own id): breadcrumb back to Prøvesvar; language picker (real Dropdown + SingleSelect, marks the choice and announces it; no translation); eyebrow (Laboratoriemedisin, or Patologi for Cytologi — assumed); title with help trigger (inert, no star); Duolist Prøvedato / Rekvirert av / Utført av (DictionaryTriggers); blueberry HighlightPanel; an ExpanderList per result with the first expander ("Prøvesvar (n)" or "Prøvesvar") open. Undersøkelse blocks are built from rows (Undersøkelse, Laboratorieresultat/Resultat, Referanseområde, Måleenhet, Funn, Prøvemateriale, Mengde, Kommentar, Vurdering, Aktuell problemstilling…), optional "Vis undersøkelseshistorikk" (inert), optional avviksmarkør ("(over øvre referanseområde)"), and for two-sided reference ranges a static SVG copy of the live Highcharts reference-range chart. Words in {braces} in the data get a dotted-underline word explanation from one ORDFORKLARINGER glossary (drafts); explanation boxes open below the whole text so sentences aren't split. Collapsed expanders whose content wasn't supplied (Detaljer om prøvesvar, Prøvemateriale (n), Resistensbestemmelse (5), Tilleggsinformasjon (n>0)) open to "Innholdet her er ikke med i prototypen ennå."
- `analyse.html?a=N` (analysis page, one per Analyseoversikt row, from the live markup for U-Bakterier dyrkning): breadcrumb back to Prøvesvar with the Analyseoversikt tab open (`index.html?fane=analyse`); eyebrow (område) + title; the analysis' explanation as ingress (U-Bakterier dyrkning: the live text with its Store medisinske leksikon source link; others: the draft glossary entry, if any, without a source); title3 "Prøvemateriale" (only where known) and "Antall prøvesvar"; a compact Table of answers (Dato linking to the result, Resultat), leaving out deleted results. No favourite star. Analysis data (with history rows) lives in `data.js` (ANALYSER, ANALYSE_INGRESS).
- **Sperre/slette (spec: vault "Prøvesvar sperre slette spec"), all 4 steps built:** the result page's title row has a "Flere valg" ⋯ button (real PopMenu: VerticalDots → X, PopOver with a LinkList; Esc/outside click closes and returns focus) whose only item is "Personvernvalg" (the page's other secondary actions, if any, are [AVKLARES]). `personvern.html?id=N` is the Personvernvalg page (§4.4): "‹ Prøvesvaret" back link, H1, result name + prøvedato, the intro copy, two LinkList rows with hints (Sperr svaret for helsepersonell / Slett svaret fra Helsenorge) and "Les mer om rettighetene dine" (#). **Block flow (step 2):** `&steg=sperr` is the §4.5 page ("Vil du sperre dette svaret?", Dette skjer / Dette endres ikke lists, warn NotificationPanel "Vær oppmerksom på" [AVKLARES akuttilgang], "Sperr svaret" / "Avbryt"). "Sperr svaret" shows a busy Loader, waits on a simulated API call (no double submit), stores the block and a log entry, then returns to the result, where a success NotificationPanel "Svaret er sperret for helsepersonell." appears under the page header and takes focus. A blocked result shows a neutral HighlightPanel with a Lock icon (title, "Du sperret svaret {dato}…", outline "Opphev sperring"); the list shows a StatusDot (DotNoEye, Figma CLD - Prøvesvar 1:496) "Sperret for helsepersonell" above the result's title; Personvernvalg's row 1 becomes "Opphev sperring". Unblocking is a Modal ("Oppheve sperringen?") → simulated API → banner removed, success NotificationPanel "Svaret er synlig for helsepersonell igjen." in its place (takes focus; ✕ closes it and returns focus to the title). **Delete flow (step 3):** `&steg=slett` is the §4.8 page ("Vil du slette dette svaret fra Helsenorge?", Dette skjer når du sletter with "**Du kan ikke lenger se svaret**", Dette endres ikke, error NotificationPanel "Dette kan ikke angres" [AVKLARES gjenoppretting], info NotificationPanel "Vil du heller sperre svaret?" + "Sperr svaret i stedet" (hidden if already blocked), the consent Checkbox, destructive "Slett svaret" + "Avbryt"). "Slett svaret" is **disabled until the consent box is ticked** (design-system disabled Button: grey fill, dashed outline); unticking disables it again. Then busy Loader → simulated API → deleted (any block is removed with it [AVKLARES 7]) and logged → `&steg=kvittering` (§4.9: success icon, "Svaret er slettet fra Helsenorge" (focused), where it's still stored, Prøvesvar/Prøvedato/Slettet summary, "Valget ditt er registrert i loggen din." + "Se logg over bruk" (→ `logg.html`, step 4), "Tilbake til prøvesvar"). Back on the list (§4.10) the result is gone from both tabs and a focused success message "**{navn}** ({dato}) er slettet fra Helsenorge." shows under the ingress. A deleted result's pages redirect to the list. **Step 4:** a failed (simulated) API call for block, unblock or delete shows `&steg=feil&handling=…` (§4.11: "Vi fikk ikke sperret svaret" / "…opphevet sperringen" / "…slettet svaret", text adapted to the current state, Veiledning Helsenorge 23 32 70 00, "Prøv igjen" / "Tilbake til svaret"; nothing changes). `logg.html` ("Logg over bruk", Pasientens prøvesvar) lists the block/unblock/delete entries newest first; linked from the list's Personvern links and the receipt. `demo.html` is a chrome-less control panel (like gravid/dashboard.html): each result's status (Synlig / Sperret dato / Slettet tid) with links, a "Simuler API-feil" switch (also `?apifeil=1` / `?apifeil=0` on any page), the log count and "Nullstill alt" (same as `index.html?nullstill=1`). State and the usage log live in the browser (localStorage); `index.html?nullstill=1` resets them.
- `data.js` holds the shared result data (RESULTATER, ORDFORKLARINGER) plus the sperre/slette state, log, simulated API, success-message (`visStatusmelding`) and busy-button helpers; `sperring.css` holds the shared styles for the flow (Button fill/outline/borderless, Loader, NotificationPanel warn/error/info/success, neutral HighlightPanel, StatusDot, Modal). Both are used by `index.html`, `resultat.html` and `personvern.html`.
- The chrome and design tokens are copied from `gravid/avslutt.html`. No shared CSS with other prototypes.
- `favicon.svg` copied from `prover-og-undersokelser/` ("P" on blueberry).
- Deployed at https://helsenorge-provesvar.netlify.app (Netlify site `helsenorge-provesvar`, created 2026-10-08).
