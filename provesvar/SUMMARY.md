# Prøvesvar

Static HTML prototype for the Helsenorge **Prøvesvar** (test results) service. Started 2026-10-08 as an empty shell; content will be built up partly from Figma.

## Current state
- `index.html`: the Helsenorge chrome only: header with profile bar, "Forside" breadcrumb (goes nowhere yet), Språk/Language switcher, a PageHeader rebuilt from the live Prøvesvar page's markup (title "Prøvesvar" and a favoritter star copied from Gravid that toggles and is remembered in the browser), the real ingress ("Her finner du svar på prøver og undersøkelser, for eksempel blodprøver, røntgen, MR eller CT."), a HelpExpanderStandalone "Velg om du vil få varsel om prøvesvar" (from the live markup; opens the live text "Du får ikke varsler automatisk når et prøvesvar er klart. Hvis du vil ha varsler, må du endre innstillingene dine." + "Gå til Tilpass varsler." (AnchorLink, `#`); same on the result pages), a Spacer (s), then a sticky white Tabs section breaking out to full width (from the live markup): **Prøvesvar** has the filter row ("Finn ..." FilterButton, inert; "N prøvesvar" count; a working "Sortering:" select by date, område or rekvirent, default newest first) and an outline PanelList of 9 white Panels (område title, rekvirent, "Prøvedato", borderless "Se resultater" with ChevronRight, not linked yet) using the live page's test data; **Analyseoversikt** (navigate by prøvesvartype, from the live markup): a "Søk i listen" FilterSearch that filters as you type (analyse, område, date; "Ingen analyser passer søket." when empty), Spacer m, and a HorizontalScroll with a sortable Table (Analyse / Område / Antall svar / Siste prøvedato; default Analyse ascending; click a header to sort, again to reverse; edge shadows when it can scroll) of the 26 analyses from the live test data. Each analysis name (AnchorLink) opens its analysis page. Then a Spacer (s); the feedback form "Hvor fornøyd er du med tjenesten Prøvesvar?" (five plum face radios, Misfornøyd … Veldig fornøyd; selecting one marks it, nothing is submitted); Spacer (l); the title2 "Personvern for Prøvesvar"; Spacer (m); a line LinkList with "Logg over bruk" and "Personverninnstillinger" (both `#`; the log page was removed 2026-10-09); then the black footer, and the desktop phone frame.
- `resultat.html?id=N` (detail page for all 9 results, rendered from a `RESULTATER` object; every "Se resultater" on the list links to its own id): breadcrumb back to Prøvesvar; language picker (real Dropdown + SingleSelect, marks the choice and announces it; no translation); eyebrow (Laboratoriemedisin, or Patologi for Cytologi — assumed); title with help trigger (inert, no star); Duolist Prøvedato / Rekvirert av / Utført av (DictionaryTriggers); blueberry HighlightPanel; an ExpanderList per result with the first expander ("Prøvesvar (n)" or "Prøvesvar") open. Undersøkelse blocks are built from rows (Undersøkelse, Laboratorieresultat/Resultat, Referanseområde, Måleenhet, Funn, Prøvemateriale, Mengde, Kommentar, Vurdering, Aktuell problemstilling…), optional "Vis undersøkelseshistorikk" (inert), optional avviksmarkør ("(over øvre referanseområde)"), and for two-sided reference ranges a static SVG copy of the live Highcharts reference-range chart. Words in {braces} in the data (and "Rekvirert av:" / "Utført av:") are DictionaryTriggers whose explanation opens in a **PopOver with a HelpBubble** (floating layer with arrow and plum ✕, like the live page; Esc, ✕ or a click outside closes it and returns focus), from one ORDFORKLARINGER glossary in `data.js` (drafts, except "Utført av:", which is the live text). Collapsed expanders whose content wasn't supplied (Detaljer om prøvesvar, Prøvemateriale (n), Resistensbestemmelse (5), Tilleggsinformasjon (n>0)) open to "Innholdet her er ikke med i prototypen ennå."
- `analyse.html?a=N` (analysis page, one per Analyseoversikt row, from the live markup for U-Bakterier dyrkning): breadcrumb back to Prøvesvar with the Analyseoversikt tab open (`index.html?fane=analyse`); eyebrow (område) + title; the analysis' explanation as ingress (U-Bakterier dyrkning: the live text with its Store medisinske leksikon source link; others: the draft glossary entry, if any, without a source); title3 "Prøvemateriale" (only where known) and "Antall prøvesvar"; a compact Table of answers (Dato linking to the result, Resultat), leaving out deleted results. No favourite star. Analysis data (with history rows) lives in `data.js` (ANALYSER, ANALYSE_INGRESS).
- **Sperre/slette (spec: vault "Prøvesvar sperre slette spec"), all 4 steps built:** the result page's title row has a "Flere valg" ⋯ button (real PopMenu: VerticalDots → X, PopOver with a LinkList; Esc/outside click closes and returns focus) whose only item is "Personvernvalg" (the page's other secondary actions, if any, are [AVKLARES]). `personvern.html?id=N` is the Personvernvalg page (§4.4): "‹ Prøvesvaret" back link, H1, result name + prøvedato, the intro copy, two LinkList rows with hints (Sperr svaret for helsepersonell / Slett svaret fra Helsenorge) and "Les mer om rettighetene dine" (#). **Block flow (step 2):** `&steg=sperr` is the §4.5 page ("Vil du sperre dette svaret?", Dette skjer / Dette endres ikke lists, warn NotificationPanel "Vær oppmerksom på" [AVKLARES akuttilgang], "Sperr svaret" / "Avbryt"). "Sperr svaret" shows a busy Loader, waits on a simulated API call (no double submit), stores the block and a log entry, then returns to the result, where the "Sperret for helsepersonell" panel is the confirmation and its heading takes focus (no separate success message, a deliberate departure from the spec). A blocked result shows a neutral HighlightPanel with a red DotNoEye icon (#A31F0E) (title, "Du sperret dette svaret {dato}. …", outline "Opphev sperring"); the list shows a StatusDot (DotNoEye, Figma CLD - Prøvesvar 1:496) "Sperret for helsepersonell" above the result's title; Personvernvalg's row 1 becomes "Opphev sperring" with the StatusDot "Du sperret dette svaret {dato}" above its label and the hint "Helsepersonell kan se det igjen hvis du opphever sperringen." Unblocking is a Modal ("Oppheve sperringen?") → simulated API → banner removed, success NotificationPanel "Svaret er synlig for helsepersonell igjen." in its place (takes focus; ✕ closes it and returns focus to the title). **Delete flow (step 3):** `&steg=slett` is the §4.8 page ("Vil du slette dette svaret fra Helsenorge?", Dette skjer når du sletter (first bullet "Svaret slettes fra det nasjonale prøvesvarregisteret."), Dette endres ikke, error NotificationPanel "Dette kan ikke angres" [AVKLARES gjenoppretting], info NotificationPanel "Vil du heller sperre svaret?" + "Sperr svaret i stedet" (hidden if already blocked), the consent Checkbox, destructive "Slett svaret" + "Avbryt"). "Slett svaret" is **disabled until the consent box is ticked** (design-system disabled Button: grey fill, dashed outline); unticking disables it again. Then busy Loader → simulated API → deleted (any block is removed with it [AVKLARES 7]) and logged → `&steg=kvittering` (§4.9: "Svaret er slettet" (focused, no icon), "Prøvesvaret er permanent fjernet fra det nasjonale prøvesvarregisteret og Helsenorge. Det er fortsatt lagret i journalen hos … og hos laboratoriet.", Prøvesvar/Prøvedato/Slettet summary, "Valget ditt er loggført." + "Se logg over bruk" (`#`), "Tilbake til prøvesvar"). Back on the list (§4.10) the result is gone from both tabs and a focused success message "**{navn}** ({dato}) er slettet fra prøvesvarregisteret." shows under the ingress. A deleted result's pages redirect to the list. **Step 4:** a failed (simulated) API call for block, unblock or delete shows `&steg=feil&handling=…` (§4.11: "Vi fikk ikke sperret svaret" / "…opphevet sperringen" / "…slettet svaret", text adapted to the current state, Veiledning Helsenorge 23 32 70 00, "Prøv igjen" / "Tilbake til svaret"; nothing changes). Block/unblock/delete events are still recorded in the browser, but the "Logg over bruk" page (`logg.html`) was removed on 2026-10-09; its links remain and go nowhere. `demo.html` is a chrome-less control panel (like gravid/dashboard.html): each result's status (Synlig / Sperret dato / Slettet tid) with links, a "Simuler API-feil" switch (also `?apifeil=1` / `?apifeil=0` on any page) and "Nullstill alt" (same as `index.html?nullstill=1`). State and the usage log live in the browser (localStorage); `index.html?nullstill=1` resets them.
- `data.js` holds the shared result data (RESULTATER, ORDFORKLARINGER) plus the sperre/slette state, log, simulated API, success-message (`visStatusmelding`) and busy-button helpers; `sperring.css` holds the shared styles for the flow (Button fill/outline/borderless, Loader, NotificationPanel warn/error/info/success, neutral HighlightPanel, StatusDot, Modal). Both are used by `index.html`, `resultat.html` and `personvern.html`.
- The chrome and design tokens are copied from `gravid/avslutt.html`. No shared CSS with other prototypes.
- `favicon.svg` copied from `prover-og-undersokelser/` ("P" on blueberry).
- Deployed at https://helsenorge-provesvar.netlify.app (Netlify site `helsenorge-provesvar`, created 2026-10-08).
