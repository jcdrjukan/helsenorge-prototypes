## 2026-09-25 — Stepper fidelity fix: wrong color/dimensions and misplaced relative to the step title
**Decision:** After a first pass at the real Stepper replica above, user flagged in a browser that it "did not appear to use the correct stepper component." Re-verified against the real source directly (not from a prior session's notes) and found genuine bugs: the marker/dot/fill color used `blueberry700` (#08667C) instead of the real `blueberry600` (#126F87) — added a proper `--blueberry-600` token, since the file only had 50/500/700 before; the track was 4px tall with 2px radius instead of the real 12px/4px; and the marker was centered via `translate(-50%,-50%)` on a percentage position, letting it visually overhang past both track ends at step 1 and step 4 — the real component positions the marker (and dots) by raw left-edge pixel offsets computed from `distanceBetweenDots = (stepperWidth - 24) / (steps - 1)`, so the 24px marker always sits flush within the track's ends, never overflowing. Also moved the stepper markup to sit *above* each step's title, matching the one real usage found in source (`frankenstein/src/behandlingshjelpemidler/OrderWizard.tsx`: back-nav → divider → Stepper → step content, whose own title renders after it) — it had been below the title.
**How verified:** Rather than trust the SCSS alone, built an isolated two-layer-gradient test page and screenshotted it at several `background-position-x` values to empirically confirm the real component's track really does render a proportional sliding dark/light fill (not a static gradient, as CSS background-sizing rules would otherwise suggest) — confirmed the fill-width formula (`min(markerPosition + 12px, stepperWidth)`, with a full-width override at the last step) matches real rendering, then reimplemented `paintStepper()` in JS using the same constants and `getBoundingClientRect()`-measured widths as the real component's algorithm, rather than a hand-guessed percentage-based approximation.
**Why:** Direct user correction after visually inspecting a live version; color and proportions are the two most visually obvious fidelity signals for a component like this, so both needed to be exactly right, not approximately right.
